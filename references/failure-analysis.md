# Failure Analysis — Dense AI Event Flyer

This file documents failure patterns the skill must actively reject.

## Failure pattern A — portal + students + dashboard

A bad result often looks like this:

- event title at the top
- explanatory paragraph
- icon row for date / team / online
- second icon row for platform / free / certificate
- track grid
- requirements module
- CTA button
- URL pill
- students in foreground
- glowing architectural portal
- futuristic skyline
- decorative microcopy everywhere

Even if the colors and rendering are polished, this is still the wrong design mode for the default skill behavior.

## Failure pattern B — literal event-name pun + brochure layout

Another bad result can be technically impressive but conceptually weak:

- the event name contains “Forge”
- the image turns that literally into a blacksmith, hammer, anvil and sparks
- six tracks appear as floating holographic cards
- the left side contains date, team size, tracks, submission requirements, certificate, prizes and CTA
- the whole poster becomes half illustration / half landing page

This is also a failure.

Why? Because the design is built from words and bullets rather than from the event's underlying promise.

A literal title pun is not automatically a concept.

## Why these fail

### 1. They illustrate the brief instead of interpreting it

Every source bullet becomes a visual module.

That is documentation, not art direction.

### 2. They create many focal points

The eye competes between title, hero, people, icon rows, tracks, CTA and URL.

There is no single dominant silhouette.

### 3. They use topic stereotypes

Hackathon / AI becomes students, code, futuristic city, glowing panels, sparks, cards and technology decoration.

These elements are semantically related but not conceptually original.

### 4. They use the event name too literally

“Forge” becomes blacksmithing.

That is predictable word association, not deep visual interpretation.

The event is really about students turning ideas into real solutions. The concept should come from that meaning, not from a dictionary-level reading of the title.

### 5. Typography behaves like UI

Text appears inside modules, pills, cards, grids and buttons.

That weakens editorial character.

### 6. The design cannot survive without copy

Remove the text and the image becomes a generic futuristic or fantasy-tech scene.

A strong key visual should remain interesting even without typography.

## Corrective behavior

When a brief contains many facts:

1. Ignore the factual list during concept invention.
2. Identify what the event means emotionally or strategically.
3. Invent one metaphor.
4. Choose one hero.
5. Use one headline.
6. Optionally include one essential fact.
7. Move the rest to the caption.

## Rejection test

Before generating, ask:

> Am I designing a poster, or laying out a brochure?

If the composition contains more than 3 distinct information zones, strongly reconsider.

If it contains a hero plus multiple icon grids, stop and simplify.

If a hackathon concept automatically became students + portal + city, reject it.

If the event title automatically became a literal prop or occupation, reject it.

If the image would still look like a generic AI-event advertisement after removing the event name, reject it.
