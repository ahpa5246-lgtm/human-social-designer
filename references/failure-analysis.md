# Failure Analysis — Dense AI Event Flyer

This file documents a failure pattern the skill must actively reject.

## The failed pattern

A bad result often looks like this:

- event title at the top
- explanatory paragraph
- icon row for date / team / online
- second icon row for platform / free / certificate
- track grid
- requirements module
- CTA button
- URL pill
- students in foreground
- glowing architectural portal
- futuristic skyline
- decorative microcopy everywhere

Even if the colors and rendering are polished, this is still the wrong design mode for the default skill behavior.

## Why it fails

### 1. It illustrates the brief instead of interpreting it

Every source bullet becomes a visual module.

That is documentation, not art direction.

### 2. It creates many focal points

The eye competes between:
- title
- portal
- people
- icon rows
- tracks
- CTA
- URL

There is no single dominant silhouette.

### 3. It uses topic stereotypes

Hackathon / AI becomes:
- students
- code
- futuristic city
- glowing portal
- icons

These elements are semantically related to the topic, but they do not form an original concept.

### 4. Typography behaves like UI

Text appears inside modules, pills, boxes, rows, or dashboard-like sections.

That weakens editorial character.

### 5. The design cannot survive without copy

Remove the text and the image becomes a generic futuristic scene.

A strong key visual should remain interesting even without typography.

## Corrective behavior

When a brief contains many facts, do this instead:

1. Ignore the factual list during concept invention.
2. Identify what the event means emotionally or strategically.
3. Invent one metaphor.
4. Choose one hero.
5. Use one headline.
6. Optionally include one essential fact.
7. Move the rest to the caption.

## Rejection test

Before generating, ask:

> Am I designing a poster, or laying out a brochure?

If the composition contains more than 3 distinct information zones, strongly reconsider.

If it contains a hero plus multiple icon grids, stop and simplify.

If a hackathon concept automatically became students + portal + city, reject it and invent something else.
